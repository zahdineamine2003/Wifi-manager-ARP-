1. 🎯 PROJECT OVERVIEW
═══════════════════════════════════════════════════════════════════════════════

WiFi Manager Pro is a comprehensive enterprise-grade network management 
application built with Python and PyQt5. It provides network administrators, 
IT professionals, and power users with advanced tools to monitor, manage, and 
control devices on their local network.

The application combines network scanning, device identification, real-time 
monitoring, security features, and remote control capabilities into a single, 
modern, user-friendly desktop application.

KEY HIGHLIGHTS:
- Real-time network device discovery and monitoring
- Advanced ARP scanning with vendor identification
- Device disconnection and network security features
- Smart TV remote control functionality
- Multi-protocol messaging system
- Live network statistics and analytics
- Professional dark-themed UI with graphs
- Cross-platform support (Windows, Linux, macOS)

8. 📨 MESSAGING SYSTEM
═══════════════════════════════════════════════════════════════════════════════

8.1 MESSAGE DELIVERY PROTOCOLS
────────────────────────────────

WEB BROWSER HIJACK ⭐ (RECOMMENDED):
• Intercepts web traffic on target device
• Displays message in browser automatically
• No setup required on target
• Works by ARP spoofing + HTTP redirect
• Configurable duration (10-300 seconds)
• Most reliable method for remote messages

WINDOWS POPUP (FORCE):
• Attempts system-level popup on Windows
• Requires WinRM/Remote Desktop enabled
• Usually blocked by security policies
• Requires administrator rights
• Best for corporate environments

UDP MESSAGING:
• Fast, connectionless protocol
• Requires message_listener.py on target
• Lightweight and efficient
• Can broadcast to multiple devices
• Port configurable (default: 9999)

TCP MESSAGING:
• Reliable, connection-oriented
• Requires open port on target
• Ensures message delivery
• Slower than UDP
• Good for critical messages

BROADCAST:
• Sends to all devices simultaneously
• Network-wide message distribution
• No individual targeting
• Good for announcements

MULTI-PROTOCOL:
• Tries multiple protocols simultaneously
• Shows success rate for each
• Maximizes delivery chance
• Detailed results per protocol

HTTP POST:
• Standard web notification
• Can trigger webhooks
• Good for API integrations
• Configurable endpoint

8.2 MESSAGE LISTENER
─────────────────────
A companion program (message_listener.py) can be installed on target devices:
• Lightweight Python GUI
• Listens on UDP port
• Shows popup notifications
• Cross-platform (Windows/Mac/Linux)
• Easy one-click setup

13. 🔧 HOW IT WORKS (TECHNICAL DETAILS)
═══════════════════════════════════════════════════════════════════════════════

13.1 ARP SCANNING PROCESS
───────────────────────────
1. User enters CIDR range (e.g., 192.168.1.0/24)
2. Application validates CIDR format
3. Generates list of IP addresses to scan
4. Creates ARP request packets for each IP
5. Sends packets using Scapy
6. Listens for ARP responses
7. Collects MAC addresses from responses
8. Optional: Performs ping for latency
9. Resolves vendor from MAC OUI
10. Updates UI with discovered devices

ARP PACKET STRUCTURE:
• Ethernet layer: Broadcast to ff:ff:ff:ff:ff:ff
• ARP layer: Who has [target IP]?
• Response contains: MAC address of target

13.2 VENDOR LOOKUP (OUI)
─────────────────────────
1. Extract first 6 hex digits from MAC (e.g., 00:1A:2B)
2. Search OUI database (downloaded from IEEE)
3. Return manufacturer name
4. Cache results for performance

OUI DATABASE:
• Downloaded from IEEE standards
• Updated automatically
• Contains ~30,000+ manufacturers
• Stored locally for offline use

13.3 DEVICE KICKING MECHANISM
───────────────────────────────
ARP SPOOFING TECHNIQUE:

Normal Communication:
Device → Router (correct MAC)

During Kick:
Device → App (spoofed as router MAC)
↓
App drops packets
↓
Device cannot reach internet

PROCESS:
1. Detect network gateway IP and MAC
2. Create ARP responses claiming to be gateway
3. Send spoofed packets to target device
4. Send spoofed packets to gateway (both directions)
5. Continue for specified duration
6. Stop to restore connectivity

13.4 MESSAGE DELIVERY
──────────────────────

WEB HIJACK PROCESS:
1. Start ARP spoofing on target device
2. Intercept HTTP requests
3. Detect browser traffic (port 80)
4. Inject HTML redirect response
5. Browser displays message page
6. Continue for specified duration
7. Stop spoofing to restore normal browsing

UDP/TCP MESSAGING:
1. Create socket connection
2. Send formatted message packet
3. Target's listener receives and displays
4. Close connection

13.5 TV CONTROL
────────────────

WAKE-ON-LAN:
1. Create magic packet (6×FF + 16×MAC)
2. Send to broadcast address
3. TV network card receives and powers on

CEC COMMANDS:
1. Detect TV brand from vendor
2. Map command to brand-specific protocol
3. Send HTTP/TCP command to TV IP
4. TV processes command

13.6 REAL-TIME MONITORING
──────────────────────────
1. QTimer triggers every 5 seconds
2. Calculate current statistics
3. Append to historical data (deque)
4. Remove oldest data if > 60 points
5. Redraw matplotlib graph
6. Update stat cards
7. Refresh UI without blocking

15. 🔒 SECURITY CONSIDERATIONS
═══════════════════════════════════════════════════════════════════════════════

15.1 ETHICAL USE WARNING
─────────────────────────
⚠️ IMPORTANT: This tool includes powerful network manipulation features that
must be used responsibly and ethically.

LEGAL CONSIDERATIONS:
• Only use on networks you own or have explicit permission to test
• ARP spoofing may be illegal in some jurisdictions
• Device kicking can disrupt critical services
• Message hijacking may violate privacy laws
• Always obtain proper authorization

15.2 REQUIRED PERMISSIONS
──────────────────────────
The application requires administrator/root privileges because:
• Raw socket access for ARP packets
• Network interface manipulation
• Packet injection capabilities
• System-level network access

15.3 SECURITY BEST PRACTICES
──────────────────────────────
FOR USERS:
• Use only on your own network
• Keep application access restricted
• Monitor usage logs
• Disable when not in use
• Keep software updated

FOR NETWORK ADMINS:
• ARP spoofing detection can identify this tool
• IDS/IPS systems may alert on ARP flooding
• Monitor for unusual ARP traffic
• Implement port security on switches
• Use DHCP snooping where possible

15.4 PRIVACY CONSIDERATIONS
────────────────────────────
• Device scanning reveals network topology
• MAC addresses can identify device owners
• Web hijacking intercepts traffic (temporarily)
• Messages may contain sensitive information
• Export files contain personal data

RECOMMENDATIONS:
• Encrypt exported CSV files
• Secure the application directory
• Delete old scan results
• Use secure channels for sharing data

16. 🔧 TROUBLESHOOTING & SUPPORT
═══════════════════════════════════════════════════════════════════════════════

16.1 COMMON ISSUES
───────────────────

ISSUE: "Permission Denied" error
SOLUTION: Run as Administrator (Windows) or with sudo (Linux/Mac)

ISSUE: No devices found during scan
SOLUTION: 
• Verify CIDR range matches your network
• Check firewall settings
• Ensure network connection is active
• Try increasing timeout value
• Disable VPN if active

ISSUE: Kick doesn't work
SOLUTION:
• Verify admin/root privileges
• Check if gateway can be detected
• Ensure target device is active
• Try increasing kick duration
• Verify no ARP protection on network

ISSUE: TV control not working
SOLUTION:
• Ensure TV is on same network
• Verify TV is powered on
• Check TV network settings
• Try Wake-on-LAN first
• Verify TV brand is supported

ISSUE: Messages not received
SOLUTION:
• Install message_listener.py on target
• Check port availability (default 9999)
• Verify firewall allows UDP/TCP
• Try different protocol
• Use Web Hijack method instead

ISSUE: Graph not updating
SOLUTION:
• Wait 5 seconds for next update
• Perform a scan to generate data
• Check logs for errors
• Restart application

16.2 PERFORMANCE OPTIMIZATION
───────────────────────────────
SLOW SCANNING:
• Reduce CIDR range (smaller network)
• Decrease timeout value
• Disable ping mode
• Close other network applications

HIGH CPU USAGE:
• Reduce scan frequency
• Disable monitoring graphs
• Close unused tabs
• Limit concurrent operations

16.3 ERROR MESSAGES
────────────────────

"CIDR invalide":
→ Format must be X.X.X.X/Y (e.g., 192.168.1.0/24)

"Un scan est déjà en cours":
→ Wait for current scan to complete

"Erreur lors de la détection de l'IP":
→ Check network connection

"No kick is currently running":
→ Start a kick operation first

"Select a device in the table first":
→ Click on a device row before performing action
